# 사진 중심 화면 배치 설계 (2026-11-23)

> **구현 후 변경(2026-11-23, 사용자 요청):** 폰에서 둥근 미니맵이 너무 작아 의미가 없어서 **뺐다**. 대신 상세를 보다가 지도 탭에 다녀와도 [사진] 탭을 누르면 보던 상세로 돌아온다(상세에서 [사진] 탭을 다시 누르면 격자). 아래 미니맵 절은 기록으로 남긴다.

## 왜

이 서비스의 핵심은 **사진을 보고 → 찾아가서 → 확인 버튼을 누르는 것**이다. 좌표를 숨기므로 지도는 내 위치와 이미 찾은 곳(별)만 보여 준다. 그런데 지금 화면은 지도가 대부분을 차지하고, 사진은 아래 작은 띠에 밀려 있으며, 장소 카드는 아래에서 올라와 보기 불편하다. 사진과 힌트를 가장 크게 보이게 하고, 지도는 필요할 때 보이되 밀려나지 않게 한다.

## 목표

- 모바일: 사진이 기본 화면. 사진 하나를 고르면 사진과 힌트가 가장 크게 보이는 상세 화면. 지도는 상세 화면의 **둥근 미니맵**(게임 미니맵 느낌)과 별도 **지도 탭**으로 늘 볼 수 있다.
- PC: 지금처럼 큰 지도 + **오른쪽 패널**(사진 격자 → 누르면 그 자리에서 상세).
- 폰의 뒤로 가기 버튼으로 상세 → 격자로 돌아온다.

## 하지 않는 것

- 랭킹 / 내 정보(마지막에 한다. 그때 탭 하나를 더한다).
- PC에서 "사진만 보고 지도에서 위치 맞히기" 같은 새 놀이 방식(사용자가 나중에 생각해 보기로 한 아이디어).
- 앱 포장(PWA 등).
- 등록 화면 내용 변경(들어가는 길만 아래 탭으로 바뀐다).
- 판정·점수·DB 변경. 이번 작업은 DB를 건드리지 않는다.

## 실패로 보는 것

- 찾기 전 장소의 좌표·이름이 화면이나 응답에 드러나는 것(지금 규칙 유지).
- 뒤로 가기를 누르면 사이트를 빠져나가 버리는 것(상세에서).
- 사진이 잘려서 장소를 알아볼 단서가 사라지는 것.

## 접근 (검토한 방법)

| 방법 | 결과 |
|---|---|
| **화면 요소 한 벌 + CSS가 너비에 따라 배치만 바꿈 (채택)** | 확인 버튼·카드 로직이 한 벌. 모바일 "격자 → 상세" 흐름을 PC 패널에서 그대로 씀 |
| PC용·모바일용 페이지를 따로 | 로직이 두 벌이 되어 고칠 때마다 두 번 고쳐야 함 |
| 화면 프레임워크 도입 | SPEC에서 빌드 도구·프레임워크를 들이지 않기로 함 |

PC 배치는 두 시안 중 B(오른쪽 패널 하나에 격자 → 상세)를 사용자가 골랐다. A(아래 띠 유지 + 상세만 오른쪽)는 목록 사진이 여전히 작다.
상세 화면은 세 시안 중 C(확인 버튼 옆 미니맵)를 골라 **미니맵을 둥글게, 미니맵 왼쪽·확인 버튼 오른쪽**(오른손 엄지 자리)으로 고쳤다.

## 화면

### 공통 상단
제목, 진행도("찾은 장소 n / 전체", 내가 올린 장소 제외 — 지금 규칙 유지), 로그인 버튼 또는 닉네임·로그아웃. PC에서는 상단에 [탐색] [등록] 메뉴가 있다. 모바일에서는 상단 메뉴를 숨기고 아래 탭을 쓴다.

- **(Claude 판단)** 상단 줄은 모든 화면에서 같다. 상세 화면은 상단을 바꾸지 않고, 패널 맨 위에 "← ???"(또는 장소 이름) 줄을 따로 둔다. 아래 그림 ②의 첫 줄이 그 패널 줄이다. 로그인 입구가 어느 화면에서나 상단에 남는다. 모바일에서 메뉴가 아래 탭으로 빠지므로 390px 한 줄에 제목·진행도·계정이 들어간다(좁으면 진행도를 "1/12"로 줄인다).

### 모바일 (너비 < 900px)

```
① 사진 탭(기본)          ② 사진 상세               ③ 지도 탭
┌ ST_cache   1/12 ┐    ┌ ← ???        1/12 ┐    ┌ ST_cache   1/12 ┐
│ ┌────┐┌────┐    │    │ ┌──────────────┐  │    │                 │
│ │ ???││★돌계단│  │    │ │   큰 사진     │  │    │   지금 탐색 지도  │
│ └────┘└────┘    │    │ └──────────────┘  │    │  ★       ●      │
│ ┌────┐┌────┐    │    │ 💡 힌트            │    │                 │
│ │ ???││ ???│    │    │ 올린 사람: 한시호   │    │                 │
│ └────┘└────┘    │    │ (◯미니맵) [📍 확인] │    │                 │
├─────────────────┤    ├───────────────────┤    ├─────────────────┤
│ 📷사진 🗺지도 ➕등록│    │ 📷사진 🗺지도 ➕등록  │    │ 📷사진 🗺지도 ➕등록│
└─────────────────┘    └───────────────────┘    └─────────────────┘
```

- **① 사진 탭:** 승인된 장소 사진을 **2열 격자**로. 찾기 전 `???`, 찾은 곳은 노란 테두리 + 별 + 이름. 내가 올린 장소도 격자에 나온다(지금처럼 "내가 올린 장소" 표시).
- **② 사진 상세:** 위에 ← (사진 탭으로), 큰 사진, 힌트, 올린 사람, 아래쪽에 **둥근 미니맵(왼쪽)** 과 **확인 버튼(오른쪽, 넓게)**. 판정 결과 문구는 확인 버튼 근처에 뜬다. 찾은 장소·내가 올린 장소의 상세 내용(이름, 이야기, 상태 문구)은 지금 장소 카드와 같다. 확인 버튼이 없는 상태(찾은 곳, 내가 올린 곳)에서도 미니맵은 보인다.
- **③ 지도 탭:** 지금 탐색 지도 그대로(내 위치, 찾은 곳 별, 캠퍼스 범위 제한). 별을 누르면 그 장소의 상세(②)로 간다.
- 아래 탭: 📷 사진 / 🗺 지도 / ➕ 등록. 상세 화면에서는 "사진" 탭이 선택된 상태로 보인다.

### PC (너비 ≥ 900px)

```
┌ ST_cache   [탐색] [등록]                       찾은 장소 1/12  닉네임 ┐
│ ┌──────────────────────────────────┐ ┌───────────────────────────┐ │
│ │                                  │ │ 찾을 장소 12               │ │
│ │            큰 지도                 │ │ [사진][사진][사진]          │ │
│ │       ★            ●             │ │ [사진][사진][사진]  (3열)   │ │
│ │                                  │ │ → 누르면 이 자리가 상세로    │ │
│ └──────────────────────────────────┘ └───────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────┘
```

- 지도가 왼쪽을 세로로 꽉 채우고, 오른쪽 패널(약 380px)에 사진 격자(3열). 사진을 누르면 패널이 상세로 바뀌고 ← 로 격자로 돌아온다.
- 지도가 늘 옆에 있으므로 **미니맵은 숨긴다.** 아래 탭도 숨긴다.
- 가짜 위치 모드(`?mock=1`)는 옆 지도를 눌러 위치를 옮긴다.

## 주소(해시 라우팅)

| 주소 | 모바일 | PC |
|---|---|---|
| `#photos` (빈 주소 포함, 기본) | 사진 탭 | 지도 + 패널(격자) |
| `#place/<장소 id>` | 사진 상세 | 지도 + 패널(상세) |
| `#map` | 지도 탭 | `#photos`와 같음 |
| `#upload` | 등록 화면 | 등록 화면 |

- 기존 `#explore`는 `#photos`로 취급한다(이미 공유된 주소 대비).
- 상세에 주소가 있으므로 **폰의 뒤로 가기로 상세 → 격자**가 된다. 상세의 ← 버튼은 `#photos`로 간다(링크로 상세에 바로 들어온 경우 뒤로 가기가 사이트 밖일 수 있어서 history.back을 쓰지 않는다).
- `#place/<id>`의 장소가 목록에 없으면(승인 전, 삭제됨, 잘못된 id) 장소 목록을 다 읽은 뒤 `#photos`로 보내고 "장소를 찾을 수 없어요" 토스트.
- **(Claude 판단) 로그인하고 돌아오면 보던 상세로 돌아온다.** 지금 `auth.js`의 `signIn()`은 돌아올 주소에서 해시를 버리고, 구글 로그인 결과가 `#access_token=…` 해시로 돌아올 수 있어 주소에 상세 id를 실어 보내면 부딪친다. 그래서 로그인 직전 지금 해시를 sessionStorage에 맡겨 두고, 로그인 상태가 정해진 뒤 되살린다(`auth.js` 수정). 로그인 결과 해시(`#access_token`, `#error` 등)는 주소 해석에서 기본 화면으로 취급한다.
- 주소 해석은 import 없는 순수 함수로 두어 Node 테스트한다(`upload-rules.js`와 같은 방식).
- 화면 너비가 바뀌어도(폰 회전, 창 크기) 주소는 그대로이고 배치만 바뀐다.

## 미니맵

- 큰 지도와 별개의 **작은 Leaflet 지도**를 하나 더 만든다(사용자 동의). 둥근 모양, 지름 약 84px.
- 손으로 움직일 수 없다(끌기·확대·축소 끔). 내 위치를 가운데에 두고 따라간다. 위치가 없으면 캠퍼스 가운데.
- 내 위치 점과 찾은 곳 별을 그린다. 찾기 전 장소는 그리지 않는다(좌표가 없다).
- 누르면 지도 탭(`#map`)으로 간다.
- OSM 타일을 쓰므로 출처 표시가 필요하다. 원 안에 넣기 어려우면 미니맵 근처에 아주 작은 "© OpenStreetMap" 글씨를 둔다.
- PC에서는 숨긴다. 숨겨져 있다가 보일 때 크기를 다시 맞춘다(`invalidateSize`).

## 사진 표시

- 격자: 정사각형 칸에 꽉 차게(잘림 허용, 고르는 용도).
- 상세: **사진 전체가 보이게**(잘리지 않게, `contain`). 높이는 화면의 절반 남짓. 힌트와 확인 버튼이 스크롤 없이 보이는 것을 우선한다(390×844 기준). 사진이 길면 사진 높이를 줄인다.

## 바뀌는 파일(예상)

- `index.html`: `#strip`, `#card` 대신 사진 패널(격자/상세), 미니맵 자리, 아래 탭. 상단 메뉴는 PC 전용.
- `style.css`: 모바일 기본 + `@media (min-width: 900px)` PC 배치.
- `js/explore.js`: 격자·상세 그리기, 미니맵, 지도 별 클릭 → 상세 주소. 확인 버튼 로직은 그대로.
- `js/main.js`: 새 주소 규칙, 아래 탭·상단 메뉴 현재 표시.
- `js/auth.js`: 로그인 전 해시를 맡겨 두고 돌아온 뒤 되살리기.
- 주소 해석 순수 함수 파일 하나 + 테스트.
- SPEC "화면" 절, README "노는 법"(사진 → 상세 → 확인)을 새 배치에 맞게 고친다.

## 만드는 사람에게 맡기는 것

- 정확한 색·간격·글자 크기(지금 스타일 톤 유지).
- 격자 칸 크기, 패널 너비의 세부 값(위 기준값 근처).
- 미니맵 확대 수준(17 근처), 출처 표시의 정확한 위치.
- 화면 전환 애니메이션 여부(없어도 됨).

## 확인 방법

- 주소 해석: Node 테스트.
- 화면: headless Chrome으로 390×844(모바일)와 1440×860(PC)에서 격자 → 상세 → 뒤로 가기, 지도 탭, 별 클릭, 미니맵 클릭, 없는 id, 너비 바꾸기, 가짜 위치로 확인 버튼(로그인 전 안내까지). 로그인 후 실제 찾기는 사용자가 폰에서 확인.
