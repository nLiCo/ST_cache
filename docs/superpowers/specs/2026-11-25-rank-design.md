# ③ 랭킹 / 내 정보 화면 설계 (짧은 설계)

2026-11-25. 작은 변경(새 화면 하나, DB 변경 없음)이라 짧게 쓴다.

## 왜

SPEC "③"의 마지막 큰 화면이다. 사용자는 점수·랭킹을 맨 마지막에 만들기로 했다가(11/23), UI 다듬기는 맨 끝에 하나씩 처리하는 편이 낫다고 보고 랭킹을 먼저 하기로 했다(11/25). 점수로 경쟁한다는 과제의 핵심이 눈에 보이게 하는 화면이다.

## 목표

- 로그인 없이 랭킹(순위·닉네임·점수·찾은 장소 수)을 본다.
- 로그인하면 같은 화면에서 내 순위 카드, 내가 찾은 장소, 내가 올린 장소와 상태(승인 대기 / 승인 / 반려)도 본다.
- 사용자가 정했다: **내 정보는 랭킹 화면 안에 넣는다**(화면 둘로 나누지 않음).

## 목표가 아닌 것

- 점수식 변경. 현재 E안은 SPEC에서 "가정"이고, 실제 데이터가 쌓인 뒤에 보너스 폭만 조정한다.
- 랭킹 목록 자르기·검색·페이지 나누기(지인 위주라 짧다).
- 새 마이그레이션. 필요한 뷰가 이미 있다.
- 관리자 화면(안 만들기로 결정).

## 하지 말아야 할 것 (실패 조건)

- 찾기 전 장소의 이름·좌표가 새 화면 어디에서도 드러나지 않는다.
- 비로그인에게 로그인 오류나 빈 화면을 보이지 않는다.

## 접근 방식

1. **등록 화면(`#upload`)과 같은 방식으로 `#rank` 화면을 하나 더 만든다. ← 선택.** 새 파일 `js/rank.js`, 화면 이름 `rank`. 기존 화면 전환 규칙(`body[data-screen]` + CSS)에 한 줄씩만 더한다.
2. 탐색 화면 안의 패널로 끼워 넣는다. 지도·격자·상세가 얽힌 전환 규칙을 건드려야 해서 버렸다.

(내 정보를 따로 둔 두 번째 화면으로 나누는 안은 사용자가 거절했다.)

## 설계

**데이터 (모두 기존, 마이그레이션 없음)**
- 랭킹: `leaderboard` 뷰(`rank`, `nickname`, `score`, `found_count`, `is_me`). 비로그인 가능. 닉네임이 없는 사람은 뷰가 거른다.
- 내 순위 카드: 위 결과에서 `is_me` 줄을 쓴다. 로그인했지만 닉네임이 없으면 카드 대신 닉네임 정하기 안내.
- 내가 찾은 장소: `public_places`에서 `found`가 참인 것(이름·이야기는 찾은 뒤에만 채워지므로 안전). 이미 `explore.js`가 불러오는 목록(`onPlacesChange`)을 재사용한다.
- 내가 올린 장소: `my_places`(대기·반려 포함). 로그인했을 때만 부른다.

**화면 (모바일)**
```
 랭킹
 내 순위 3위 · 42.5점 · 찾은 장소 4곳      (로그인 시)
 1  민수      52.0점  5곳
 2  지연      47.3점  5곳
 3  한시호    42.5점  4곳     ← 내 줄 강조
 ── 내가 찾은 장소 ──
 ── 내가 올린 장소 ──   돌계단 [승인 대기]
```
비로그인이면 위에 "로그인하면 내 순위가 보여요"만 더하고 랭킹 목록은 그대로 보인다.

**주소·메뉴**
- `routes.js`: `#rank` → `{ screen: "rank" }`. 순수 함수라 기존 테스트에 케이스를 더한다. `restoreHash`는 기본 화면이 아닌 주소를 되살리므로 `#rank`도 그대로 동작한다.
- `main.js`: `TAB_FOR`/`MENU_FOR`에 `rank` 추가. `rank.js`의 보이기/숨기기 함수를 `setUploadVisible`처럼 부른다.
- `index.html`: 아래 탭에 4번째 `🏆 랭킹`, PC 상단 메뉴에 "랭킹". `style.css`: `#rank` 영역(등록 화면과 같은 위치 규칙), 4칸 탭 폭.

**불러오는 때**
- 화면에 들어올 때마다 다시 불러온다(다른 사람이 찾으면 점수가 바뀌므로). 로그인·로그아웃으로 상태가 바뀌어도 다시 그린다.
- 실패하면 "불러오지 못했어요" 한 줄과 다시 시도 버튼. 빈 화면을 남기지 않는다.
- `?mock=1`은 위치만 가짜라서 랭킹도 DB에서 그대로 불러온다.

**검증**
- Node 테스트: `parseRoute("#rank")`, 순위 줄 문구 만드는 순수 함수(있다면).
- headless Chrome으로 비로그인 화면 확인. 로그인이 필요한 부분은 사용자가 확인한다(기존 방식).

## 점수 점검 결과 (새 변경 없음)

- `place_score`: `check_place`로만 기록하면 찾은 수 ≤ 시도 수가 성립해(`attempts`를 먼저 넣은 뒤 `finds`를 넣음) 최소값이 10보다 크고 음수·0 나눗셈이 없다. SQL Editor로 직접 넣거나 지우면 깨질 수 있다.
- 실제 데이터(공개 키로 `leaderboard` 조회, 2026-11-25): 6명, 점수 95.3 / 39.2 / 27.0 / 12.5 / 12.0 / 0.0, `rank`·`score`·`found_count`는 JSON 숫자로 온다. 관리자 `nLiCo`는 0점으로 맨 아래. 비로그인이라 `is_me`는 모두 false.
- `leaderboard`: 승인된 장소만 센다. 올린 사람은 자기 장소를 못 찾으므로 점수가 0이다. 지금 관리자 계정은 12곳을 올려서 0점으로 맨 아래에 나온다(의도한 동작).
- 점수는 부동소수 합을 `round(…, 1)`로 보여 준다. 동점이면 같은 순위(`rank()`)다.

## 내 판단으로 정한 것 (사용자가 고칠 수 있음)

- 랭킹은 전체를 보여 준다. 길어지면 그때 자른다.
- 닉네임 없는 사용자는 랭킹에 안 나온다(뷰 그대로).
- 화면에 들어올 때마다 새로 불러온다(주기 갱신 없음).
- 올린 장소 상태 문구는 "승인 대기 / 승인 / 반려"로 쓴다.
