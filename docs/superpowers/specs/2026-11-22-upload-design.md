# ② 장소 등록 화면 설계 (2026-11-22)

SPEC "② 장소 등록" 절을 구현하기 위한 짧은 설계. SPEC에 이미 있는 내용(글자 수 제한, 등급별 승인, DB 트리거)은 다시 적지 않는다.

## 목적

로그인한 사람이 현장에서 사진을 찍어 장소를 올린다. 좌표가 사진을 찍은 자리와 맞는 것이 가장 중요하다(돌계단 EXIF 46m 어긋남 사례).

## 접근 (검토한 방법)

| 안 | 내용 | 결과 |
|---|---|---|
| A. 사진을 찍은 순간 위치 | 카메라에서 돌아온 순간 위치를 고정. 위치가 오래되거나 나쁘면 대기 + 60초 시간 초과 | 카메라가 떠 있는 동안 위치 갱신이 멈출 수 있어 처리가 복잡 |
| B. 등록 버튼을 누른 순간 위치 | 가장 단순 | 글을 쓰며 움직이면 좌표가 사진 자리에서 어긋남 |
| **C. 카메라 버튼을 누른 순간 위치 (채택)** | 카메라를 열기 전에 정확도를 확인하고, 버튼을 누르는 순간 위치를 고정 | 사용자 제안. A의 장점을 유지하면서 대기·시간 초과가 필요 없음 |

## 화면 흐름

```
┌ ST_cache   [탐색] [등록]        닉네임 ┐
│ 현재 위치 정확도: ±42m                  │
│ ⚠ 이 자리에 서서 잠시 기다려 주세요      │
│ [📷 사진 찍기]  ← 30m 이하가 되면 켜짐   │
│ ─────────────────────────────────────  │
│ (사진 미리보기)   위치 고정됨 ±12m       │
│ 이름*  [            ] 0/30             │
│ 힌트   [            ] 0/100            │
│ 이야기 [            ] 0/500            │
│ [등록하기]                             │
└────────────────────────────────────────┘
```

1. 현재 정확도를 실시간으로 보여 준다(`geo.js`의 `onPosition`).
2. 정확도 30m 이하이고 30초 안에 갱신된 위치(`hasFreshPosition`)일 때만 "사진 찍기" 버튼이 켜진다. 아니면 "이 자리에 서서 잠시 기다려 주세요".
3. 버튼을 누르는 순간 위치와 시각을 `pinned`에 고정하고 숨은 `<input type="file" accept="image/*" capture="environment">`를 연다. 다시 찍으면 새로 고정한다.
4. 사진이 돌아오면 촬영 시각을 검사한다(아래). 통과하면 미리보기와 "위치 고정됨 ±n m"를 보여 준다.
5. 이름(필수 30자), 힌트(100자), 이야기(500자)를 적고 등록한다. 글자 수 표시.
6. 사진을 긴 변 1280px로 줄여 JPEG로 재인코딩(EXIF 제거) → `photos` 버킷 `<user id>/<crypto.randomUUID()>.jpg`에 업로드 → `places`에 insert(`name, hint, story, photo_path, lat, lng, accuracy` = `pinned` 값).
7. 성공하면 `profile.role`로 안내: `user` → "승인 대기", `trusted`/`admin` → "바로 공개". 입력 칸을 비운다. 탐색 장소 목록을 다시 읽는다.

## 오래된 사진 막기

- 기준: **사진 촬영 시각 ≥ 카메라 버튼을 누른 시각 − 1분**. 같은 폰 시계로 비교하므로 여유는 1분.
- 촬영 시각: EXIF `DateTimeOriginal`이 있으면 그것, 없으면 `file.lastModified`.
- EXIF는 `exifr`를 CDN으로 불러와 읽는다(EXIF를 지우기 전에 읽음). 빌드 도구 없음.
- 통과 못 하면 "방금 찍은 사진만 올릴 수 있어요. 다시 찍어 주세요" + 등록 막기.
- 한계: 브라우저 검사라 콘솔로 건너뛸 수 있다. 지인 위주로 시작하므로 실수 방지 수준이면 충분하다(가짜 위치를 막지 않는 것과 같은 판단).
- 아이폰에서 갤러리 사진의 `lastModified`가 고른 시각으로 나오는지는 미확인. 폰에서 확인한다.

## 해시 라우팅

- 상단에 [탐색] [등록] 메뉴. `#explore`(기본), `#upload`. 랭킹 탭은 ③에서 더한다.
- `main.js`가 `hashchange`로 화면을 바꾼다. 탐색 화면 요소(지도, 사진 띠, 카드)를 숨기고 등록 화면을 보인다.
- 탐색으로 돌아오면 Leaflet `map.invalidateSize()`.
- 위치 추적은 화면과 상관없이 계속 돈다.

## 지도 범위 제한 (같이 넣기로 함)

- 탐색 지도를 캠퍼스 주변으로 제한한다: `maxBounds`(캠퍼스 경계 + 사방 약 150m, 가장자리 별·카드가 잘리지 않게), `maxBoundsViscosity: 1.0`, `minZoom` 16 정도.
- 목적은 엉뚱한 곳으로 끌려가지 않게 하는 것. 지도 조각은 원래 보이는 부분만 받으므로 데이터 절약 효과는 거의 없다.
- 캠퍼스 밖에서는 내 위치 점이 안 보인다. 캠퍼스 안에서만 쓰는 서비스라 괜찮다.

## 상태별 등록 화면

- 로그인 전: 로그인 안내와 로그인 버튼만.
- 닉네임 전: 닉네임 정하기 버튼만.
- 가짜 위치 모드(`?mock=1`): 탐색 지도에서 마지막으로 찍은 위치를 쓴다. 없으면 "탐색 지도에서 먼저 위치를 찍어 주세요".

## 만들지 않는 것 / 내 판단으로 둔 것

- 장소 insert가 실패해도 이미 올라간 사진은 남는다. 사진 삭제 RLS 규칙이 없고, 드문 경우라 그냥 둔다.
- insert 후 줄을 다시 읽지 않는다(select 권한 없음). 안내는 등급으로 정한다.
- DB 변경 없음.
