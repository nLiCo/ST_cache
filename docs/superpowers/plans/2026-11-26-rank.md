# ③ 랭킹 / 내 정보 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 등록 점수를 랭킹 점수에 합치는 마이그레이션과, 랭킹·내 정보를 보여 주는 `#rank` 화면을 만든다.

**Architecture:** 점수는 저장하지 않고 DB 뷰가 볼 때마다 계산한다. 새 순수 SQL 함수 `upload_score`와 `leaderboard`·`my_places` 뷰 변경을 마이그레이션 하나로 묶고, 사용자가 SQL Editor에서 실행한다. 화면은 등록 화면과 같은 방식(`body[data-screen]` + CSS)의 새 화면 `rank`이고, 문구 만드는 판단은 import 없는 `js/rank-rules.js`에 두어 Node로 테스트한다.

**Tech Stack:** Supabase Postgres(뷰, SQL 함수, 권한), 순수 HTML/CSS/JS(ES 모듈), Supabase JS 2.119.0(CDN), 테스트 `node --test "tests/*.test.mjs"`, 화면 확인은 headless Chrome + CDP 스크립트.

**Spec:** `docs/superpowers/specs/2026-11-25-rank-design.md`

## Global Constraints

- 등록 점수(장소 하나) = `6 × min(찾은 사람 수, 5) × (1 − (찾은 사람 수 + 1) / (시도한 사람 수 + 2))`. 승인된 장소만. 대기·반려는 0.
- 사용자 점수 = 찾기 점수 합(기존 `place_score`) + 등록 점수 합. 저장하지 않는다.
- `leaderboard`에서 `role = 'admin'`인 사람은 줄에서 뺀다. 관리자의 시도·찾기는 다른 장소의 찾은·시도 수에 그대로 센다.
- `create or replace view`는 맨 뒤에 칸을 더하는 것만 된다. 기존 칸의 순서·이름·타입을 바꾸지 않는다.
- 새 마이그레이션은 사용자가 SQL Editor에 붙여 넣어 실행한다(Supabase CLI 안 씀). **화면 배포 전에 실행한다.**
- 찾기 전 장소의 이름·좌표가 새 화면에 드러나지 않는다. 비로그인에게 오류·빈 화면을 보이지 않는다.
- 점수 표시는 소수 한 자리. 상태 문구는 "승인 대기 / 승인 / 반려".
- 빌드 도구·npm 의존성 없음. 문구는 한국어 "~요"체. 커밋은 Conventional Commits, 한국어, 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. 마이그레이션을 아직 실행하지 않은 상태로 랭킹 화면 열기 → "불러오지 못했어요" + 다시 시도 버튼(빈 화면 아님). (Task 3 확인 단계)
2. 관리자 계정으로 로그인 → 내 순위 대신 "관리자 계정은 랭킹에 나오지 않아요", 목록에 관리자 없음. (Task 1 SQL 확인 + 사용자 확인)
3. 랭킹 화면에 있는 동안 로그인·로그아웃 → 내 정보 부분이 새 상태로 다시 그려진다. (Task 3 확인 단계, 로그인 부분은 사용자)
4. 랭킹에서 장소를 눌러 상세 → ← → 랭킹으로 돌아온다. (Task 3 확인 단계)
5. 동점 → 같은 순위 숫자. (Task 1 SQL은 `rank()` 유지, Task 2 문구 테스트)

### Task 1: 등록 점수 마이그레이션

**Files:**
- Create: `supabase/migrations/20261126120000_upload_score.sql`

**Interfaces:**
- Produces (DB):
  - `public.upload_score(finders bigint, attempters bigint) returns double precision` — `language sql immutable`, `set search_path = ''`, 표를 읽지 않음. `revoke execute … from public`, `grant execute … to anon, authenticated`(`place_score`처럼 뷰를 읽는 사람이 실행할 수 있어야 함).
  - `public.leaderboard` 칸(순서 그대로): `rank`, `nickname`, `score`(= 찾기 + 등록, `round(…::numeric, 1)`), `found_count`, `is_me`, 그리고 맨 뒤에 `find_score`, `upload_score`(각각 `round(…::numeric, 1)`), `upload_count`(승인된 올린 장소 수, bigint). `rank`는 반올림 전 총점 내림차순 `rank()`. `where pr.nickname is not null and pr.role <> 'admin'`.
  - `public.my_places` 칸: 기존 `id, name, hint, story, photo_path, status, created_at` 뒤에 `finder_count`(bigint), `upload_score`(`status = 'approved'`면 `upload_score(찾은 수, 시도 수)`, 아니면 0, double precision).
- 찾은 수·시도 수는 기존 `leaderboard`처럼 장소별 `count(*)` 부분 질의로 센다. 기존 권한(grant)은 `create or replace view`가 유지한다.

### Task 2: 랭킹 문구 규칙 `js/rank-rules.js` + `#rank` 주소

**Files:**
- Create: `js/rank-rules.js`, `tests/rank-rules.test.mjs`

**Interfaces:**
- Produces (`rank-rules.js`, 순수 함수, import 없음):
  - `formatScore(n: number) -> string` — 소수 한 자리(`(42.5).toFixed(1)` 식), `null`·`undefined`는 `"0.0"`.
  - `scoreBreakdown(row: {score, find_score, upload_score}) -> string` — `"42.5점 (찾기 30.5 · 등록 12.0)"`.
  - `statusLabel(status: "pending"|"approved"|"rejected") -> string` — `"승인 대기"` / `"승인"` / `"반려"`.
  - `uploadedPlaceNote(place: {status, finder_count, upload_score}) -> string` — 승인이고 찾은 사람 0명: `"아직 찾은 사람이 없어요"`; 승인이고 n명: `"n명이 찾았어요 · +X.X점"`; 승인 아님: `""`.
- Produces (`routes.js`): `parseRoute("#rank") -> { screen: "rank", placeId: null }`.

- [ ] **Step 1: 실패하는 테스트 쓰기**

```js
test("formatScore", () => {
  assert.equal(formatScore(42.5), "42.5");
  assert.equal(formatScore(12), "12.0");
  assert.equal(formatScore(null), "0.0");
});
test("scoreBreakdown", () => {
  assert.equal(scoreBreakdown({ score: 42.5, find_score: 30.5, upload_score: 12 }), "42.5점 (찾기 30.5 · 등록 12.0)");
});
test("statusLabel", () => {
  assert.equal(statusLabel("pending"), "승인 대기");
  assert.equal(statusLabel("approved"), "승인");
  assert.equal(statusLabel("rejected"), "반려");
});
test("uploadedPlaceNote", () => {
  assert.equal(uploadedPlaceNote({ status: "approved", finder_count: 0, upload_score: 0 }), "아직 찾은 사람이 없어요");
  assert.equal(uploadedPlaceNote({ status: "approved", finder_count: 3, upload_score: 9.8 }), "3명이 찾았어요 · +9.8점");
  assert.equal(uploadedPlaceNote({ status: "pending", finder_count: 0, upload_score: 0 }), "");
});
// routes.test.mjs에 추가
test("parseRoute: 랭킹", () => assert.deepEqual(parseRoute("#rank"), { screen: "rank", placeId: null }));
test("restoreHash: 랭킹도 되살린다", () => assert.equal(restoreHash("#rank", ""), "#rank"));
```
